# 探索的テストチャーター一覧：ツアー観点から作る実務用カタログ

用途: 整理済みの探索的テストツアーを、実行可能な探索的テストチャーターへ変換するための実務用カタログ

対象: QAエンジニア、テスト設計者、SET、QAリード、プロダクト品質責任者、AIエージェントによる探索的テスト設計者

---

## 0. 結論

ツアー一覧を整備した後は、次にチャーター一覧を整備するとよい。

ツアーは探索観点の辞書であり、チャーターは1回の探索セッションで実行するミッションである。したがって、ツアーをそのまま実行するのではなく、対象機能、利用条件、発見したいリスクを明確にしたチャーターへ変換することで、探索的テストをチームで再利用しやすくなる。

本ドキュメントでは、各チャーターに次を含める。

| 項目 | 内容 |
| --- | --- |
| チャーター名 | 実務で使いやすい目的ベースの名称 |
| 対応ツアー・観点 | 元になる探索的テストツアーや品質観点 |
| チャーター文 | `Explore / With / To discover` 形式のミッション |
| 説明 | 何を狙うチャーターか |
| 使用する時 | どのようなプロダクト状態・変更・リスクで使うか |
| サンプル操作の流れ | 実際の探索セッションでの進め方 |
| 主な成果物 | セッション後に残す情報 |

---

## 1. チャーター設計の基本

### 1.1 推奨テンプレート

```
Explore: 探索対象
With: 使用する観点、データ、条件、ツール、環境
To discover: 発見したいリスク、不具合、不明点、品質情報
```

例:

```
Explore: 注文確定から請求作成、通知までの流れ
With: Money Tour、FedEx Tour、Rained-Out Tour、複数タブ、通信断
To discover: 二重請求、請求漏れ、通知不整合、キャンセル後の残骸データ
```

### 1.2 セッション運用の最小ルール

| 項目 | 推奨 |
| --- | --- |
| タイムボックス | 45〜90分を目安にする。長すぎる場合はチャーターを分割する |
| 事前準備 | 対象機能、テストデータ、利用ロール、観測手段を用意する |
| 実行中メモ | 操作、発見、疑問、環境、証跡、次に試したいことを残す |
| デブリーフィング | バグ、リスク、仕様確認、追加チャーターを整理する |
| 注意 | チャーターは詳細手順書ではない。探索の余白を残す |

# 4. チャーター詳細

## A. プロダクト理解・基本機能

### C01. 全体把握チャーター（P0）

**対応ツアー・観点:** Feature Tour / Structure Tour / Parking Lot Tour

**チャーター文:**

```
Explore: プロダクト全体の画面・機能・主要導線 / With: メニュー巡回、画面遷移、権限別アカウント、簡易メモ / To discover: 未把握機能、明白な不具合、次に深掘りすべき領域
```

**説明:** 初回接触時に、対象システムの地図を作るためのチャーター。

**使用する時:** 新規プロダクト、担当変更直後、仕様が薄い、テスト戦略を作る前、AIエージェントに探索させる前の地図作り。

**サンプル操作の流れ:**

1. 主要ロールでログインする
2. トップ画面、メニュー、設定、ヘルプ、通知、管理機能を巡回する
3. 各画面で主要操作ボタン、入力欄、出力、外部リンクをメモする
4. 明らかに壊れている箇所、仕様確認が必要な箇所、リスクが高そうな箇所をマーキングする
5. 次セッション用に深掘りチャーター候補を作る

**主な成果物:** 機能マップ、リスクメモ、未確認事項、次チャーター候補

### C02. ガイド・ドキュメント準拠チャーター（P0）

**対応ツアー・観点:** Guidebook Tour / Documentation Tour

**チャーター文:**

```
Explore: ヘルプ・マニュアル・チュートリアルに記載された操作 / With: 公開ドキュメント、FAQ、オンボーディング手順 / To discover: ドキュメントと実挙動の不一致、案内不足、初回利用の詰まり
```

**説明:** ユーザーに提示している手順どおりに操作し、説明責任が破綻していないかを見るチャーター。

**使用する時:** 新機能リリース、ヘルプ更新後、オンボーディング改善、サポート問い合わせが多い機能。

**サンプル操作の流れ:**

1. 対象ドキュメントから操作手順と主張を抜き出す
2. 記載順に操作し、画面名、文言、ボタン名、期待結果を照合する
3. 手順から少し外れた操作も試す
4. 説明と異なる結果、曖昧な説明、古い画像、到達不能な導線を記録する
5. ドキュメント修正か実装修正かを分類する

**主な成果物:** ドキュメント不整合一覧、UX改善候補、仕様確認事項

### C03. 主張検証チャーター（P0）

**対応ツアー・観点:** Claims Tour / Critic派生 / Blogger派生

**チャーター文:**

```
Explore: LP、営業資料、UI文言、リリースノート、レビューで主張されている機能 / With: 主張リスト、実データ、代表的ユーザー条件 / To discover: 主張と実挙動の不一致、誤解を招く表現、保証できない品質
```

**説明:** プロダクトが外部・内部で何を約束しているかを検証するチャーター。

**使用する時:** マーケティング表現が強い機能、営業デモ対象、リリースノート公開前、カスタマーサクセスから違和感が上がった時。

**サンプル操作の流れ:**

1. LP、ヘルプ、リリースノート、UI文言から検証対象の主張を抽出する
2. 各主張に対して再現条件と判定基準を置く
3. 標準条件、境界条件、例外条件で実行する
4. 主張どおりでない挙動、条件付きでしか成立しない挙動を記録する
5. 文言修正、仕様補足、実装修正に分けて提案する

**主な成果物:** 主張検証表、過剰表現リスク、リリース前修正候補

### C04. 主要ユーザージャーニーチャーター（P0）

**対応ツアー・観点:** User Tour / Scenario Tour / User Journey Tour

**チャーター文:**

```
Explore: ユーザーが目的を達成する一連の流れ / With: ペルソナ、業務シナリオ、代表データ、複数ロール / To discover: 目的達成を阻害する導線、情報不足、状態不整合
```

**説明:** 単機能ではなく、ユーザーの目的達成を軸に探索するチャーター。

**使用する時:** リリース判定、E2E品質確認、初回利用改善、主要業務フローの品質評価。

**サンプル操作の流れ:**

1. 対象ペルソナと目的を1つ決める
2. 開始点、完了条件、途中で必要な情報を定義する
3. 実際の業務に近いデータで最初から最後まで操作する
4. 迷い、戻り、保存、再開、通知、履歴確認を含めて試す
5. 目的達成を阻害した要因を機能・文言・性能・権限に分類する

**主な成果物:** ジャーニー上の障害、改善バックログ、ユーザー視点の品質メモ

### C05. マネーフローチャーター（P0）

**対応ツアー・観点:** Money Tour / Skeptical Customer Tour

**チャーター文:**

```
Explore: 売上・契約・継続利用に直結するフロー / With: 主要プラン、クーポン、支払い方法、顧客質問、営業デモ条件 / To discover: 購入不能、二重請求、契約不整合、デモ崩壊リスク
```

**説明:** 事業影響の大きい不具合を狙うチャーター。

**使用する時:** 決済、契約、課金、見積、注文、予約、申請など、失敗時の事業影響が大きい機能。

**サンプル操作の流れ:**

1. 収益・契約に直結する主要フローを選ぶ
2. 通常購入、割引、変更、キャンセル、失敗、再試行の条件を用意する
3. ユーザーと管理者の両視点で実行する
4. 請求、在庫、契約状態、通知、履歴、外部決済結果を照合する
5. 二重処理、漏れ、不正な成功表示を重点的に記録する

**主な成果物:** 事業影響バグ、決済・契約整合性メモ、リリース阻害リスク

### C06. ランドマーク連携チャーター（P1）

**対応ツアー・観点:** Landmark Tour / Mixed-Destination派生

**チャーター文:**

```
Explore: 主要機能同士の遷移と組み合わせ / With: 重要機能リスト、実行順序の入れ替え、途中保存、戻る操作 / To discover: 機能間の状態不整合、導線不備、連携漏れ
```

**説明:** 主要機能を目印にして、順番や組み合わせを変えながら探索するチャーター。

**使用する時:** 複数機能が同じデータを共有する、リリース前の主要導線確認、業務フローが長い場合。

**サンプル操作の流れ:**

1. 主要機能を3〜5個選びランドマークとして並べる
2. 標準順序で一巡する
3. 順序を入れ替える、途中で戻る、別画面に移動する
4. 各機能で同じデータの表示・状態・権限が一致するか確認する
5. 矛盾や失われた状態を記録する

**主な成果物:** 機能連携不具合、遷移図の修正候補、状態不整合メモ

### C07. 脇役・周辺体験チャーター（P1）

**対応ツアー・観点:** Supporting Actor Tour / Back Alley Tour

**チャーター文:**

```
Explore: 主要機能の周辺にある補助機能 / With: レビュー、履歴、印刷、共有、ヘルプ、関連リンク / To discover: 周辺体験の破綻、補助機能の品質低下、主要機能への副作用
```

**説明:** メイン機能の近くにあるが、テストで後回しにされがちな補助機能を見るチャーター。

**使用する時:** 主要フローの周辺に通知、履歴、レビュー、共有、補助設定が多い場合。

**サンプル操作の流れ:**

1. 主要機能を1つ選ぶ
2. 周辺にある補助機能を列挙する
3. 主要操作の前後で補助機能を使う
4. 補助機能の更新が主要データや通知に影響するか確認する
5. ユーザー体験上の違和感と機能不具合を分けて記録する

**主な成果物:** 周辺機能の不具合、体験改善候補、主要機能への副作用

### C08. 見つけにくい機能チャーター（P2）

**対応ツアー・観点:** Scottish Pub Tour / Back Alley Tour

**チャーター文:**

```
Explore: 深い階層、低頻度、到達困難な機能 / With: メニュー探索、検索、権限別アカウント、古い導線 / To discover: 到達不能、放置バグ、権限不備、古い仕様の残骸
```

**説明:** 大規模アプリで埋もれている機能を探索するチャーター。

**使用する時:** 長寿命プロダクト、大規模管理画面、低頻度ながら重要な機能、問い合わせ時だけ使う機能。

**サンプル操作の流れ:**

1. メニュー階層の深い機能を抽出する
2. 権限別に到達できるか確認する
3. 古いデータ、新しいデータ、空データで実行する
4. 主要機能と組み合わせて副作用を確認する
5. 到達性、利用不能、表示崩れ、仕様不明点を記録する

**主な成果物:** 放置領域のリスク、削除候補、改善候補、仕様確認事項

## B. データ・状態・連携

### C09. データライフサイクルチャーター（P0）

**対応ツアー・観点:** FedEx Tour / Data Tour

**チャーター文:**

```
Explore: 主要データの作成・更新・参照・削除・同期 / With: 複数画面、API、DB確認、通知、外部連携 / To discover: データ欠落、反映漏れ、削除漏れ、同期不整合
```

**説明:** データを荷物のように追跡し、どこで作られ、変換され、保存され、使われ、消えるかを見るチャーター。

**使用する時:** 注文、請求、顧客、申請、予約、在庫など、同じデータが複数機能で使われる場合。

**サンプル操作の流れ:**

1. 追跡する主要データを1つ決める
2. 作成、編集、承認、取消、削除、復元などのイベントを実行する
3. 一覧、詳細、通知、履歴、帳票、API、外部システムで同じデータを確認する
4. 途中で失敗、戻る、再実行を挟む
5. データの値、状態、タイムスタンプ、所有者、監査ログの整合性を記録する

**主な成果物:** データフロー図、不整合一覧、削除・同期・履歴の問題

### C10. 状態遷移チャーター（P0）

**対応ツアー・観点:** State Transition Tour / Rained-Out Tour / Obsessive-Compulsive Tour

2. 途中失敗、部分成功、外部API失敗、再起動を発生させる

4. 同じ処理を再実行し、二重処理がないか確認する
5. 復旧手順、ログ、通知、ユーザー案内を記録する

**主な成果物:** 復旧不具合、運用手順改善、レジリエンスリスク

## H. AI・LLMプロダクト

### C45. AI出力妥当性・主張検証チャーター（P0）

**対応ツアー・観点:** AI/LLM Risk Tour / Claims Tour / Testability Tour

**チャーター文:**

```
Explore: AI機能がユーザーに提示する回答・要約・分類・提案 / With: 既知正解データ、曖昧入力、境界ケース、根拠確認 / To discover: 誤回答、根拠不明、過剰な断定、ユーザー誤誘導
```

**説明:** AI出力がプロダクトの約束に対して妥当かを見るチャーター。

**使用する時:** AI検索、要約、分類、提案、コード生成、QA回答、意思決定支援、サポートボット。

**サンプル操作の流れ:**

1. AI機能が約束している成果と禁止事項を整理する
2. 正解が分かる入力、曖昧な入力、境界ケースを用意する
3. 同一入力と類似入力で複数回実行する
4. 回答、根拠、引用、信頼度、免責、次アクションを確認する
5. 誤回答、過剰断定、再現性、ユーザー影響を記録する

**主な成果物:** AI出力品質リスク、評価データ候補、ガードレール改善案

### C46. プロンプトインジェクションチャーター（P0）

**対応ツアー・観点:** AI/LLM Risk Tour / Saboteur Tour / Antisocial Tour

**チャーター文:**

```
Explore: ユーザー入力・外部文書・Issue本文・Webページを読むAI機能 / With: 直接/間接プロンプト注入、悪意ある文書、権限差分 / To discover: 指示乗っ取り、秘密情報出力、不正なツール実行、ポリシー逸脱
```

**説明:** LLMが外部入力の指示に乗っ取られないかを探索するチャーター。

**使用する時:** RAG、AIエージェント、外部Web/ドキュメント読取、Issue/PR処理、メール処理、チャットボット。

**サンプル操作の流れ:**

1. AIが読む入力源と実行可能なツールを整理する
2. 通常文書で期待動作を確認する
3. 文書内に隠れた指示、ロール変更要求、秘密情報要求、ツール実行要求を含める
4. 権限違いユーザーや制限付き環境で実行する
5. AIの出力、ツール呼び出し、ログ、承認要求の有無を記録する

**主な成果物:** プロンプト注入リスク、権限分離改善、ツール制御改善案

### C47. 過剰自律性・安全停止チャーター（P0）

**対応ツアー・観点:** AI/LLM Risk Tour / Permission Boundary Tour / Testability Tour

**チャーター文:**

```
Explore: AIエージェントの自律操作、ツール実行、変更提案 / With: 権限最小化、承認要求、危険操作、停止操作、監査ログ / To discover: 不要な変更、削除・送信・購入などの過剰操作、停止不能、監査不能
```

**説明:** AIが勝手にやりすぎないかを見るチャーター。

**使用する時:** AIエージェント、コード修正、メール送信、チケット更新、ファイル操作、DB操作、購買/契約操作。

**サンプル操作の流れ:**

1. AIが実行できるツールと権限を整理する
2. 安全な操作と危険な操作の境界を定義する
3. 曖昧な依頼、過剰な依頼、権限外の依頼を与える
4. 承認要求、拒否、停止、差し戻し、ロールバックが働くか確認する
5. 実行ログ、変更差分、ユーザー通知を記録する

**主な成果物:** 過剰自律性リスク、承認フロー改善、権限制御改善案

### C48. AI機密情報・RAG境界チャーター（P0）

**対応ツアー・観点:** AI/LLM Risk Tour / Privacy Tour / Permission Boundary Tour

**チャーター文:**

```
Explore: RAG文書、会話履歴、ツール出力、ログに含まれる機密情報 / With: 権限差分、テナント差分、誘導質問、要約、引用 / To discover: 権限外情報露出、秘密情報の要約混入、ログ漏洩、引用元誤表示
```

**説明:** AIが参照できる情報の境界と出力先を探索するチャーター。

**使用する時:** 社内ナレッジ検索、顧客別文書検索、サポートAI、コードベースQA、会話履歴利用、マルチテナントAI。

**サンプル操作の流れ:**

1. AIが参照可能なデータソースと権限を整理する
2. Aユーザーのみ参照可能な文書を用意する
3. Bユーザーで直接質問、要約要求、引用要求、遠回しな質問を試す
4. 回答本文、引用、根拠、ログ、キャッシュを確認する
5. 権限外露出、過剰な引用、削除済みデータ参照を記録する

**主な成果物:** RAG権限リスク、機密情報露出、データ境界改善案

### C49. 非決定性・再現性チャーター（P1）

**対応ツアー・観点:** AI/LLM Risk Tour / Testability Tour

**チャーター文:**

```
Explore: 同一・類似入力に対するAI出力の揺らぎ / With: 同一プロンプト反復、温度設定、モデル差分、時系列比較 / To discover: 品質ばらつき、再現困難、評価不能、ユーザー体験の不安定さ
```

**説明:** AI出力の揺らぎがプロダクト品質として許容できるかを見るチャーター。

**使用する時:** 生成AI、分類、ランキング、要約、推奨、AIレビュー、AIエージェントの計画生成。

**サンプル操作の流れ:**

1. 基準入力と期待する品質基準を決める
2. 同一入力を複数回実行する
3. 類似入力、順序変更、文体変更、モデル/設定変更で実行する
4. 出力の差分、根拠、危険な揺らぎ、許容可能な揺らぎを分類する
5. 再現条件、ログ、評価データ化できるケースを記録する

**主な成果物:** 出力揺らぎ分析、評価データ候補、再現性改善案

### C50. 人間介入・承認・監査チャーター（P0）

**対応ツアー・観点:** AI/LLM Risk Tour / Testability Tour / Observability Tour

**チャーター文:**

```
Explore: AIが重要操作を行う前後の人間介入ポイント / With: 承認、差し戻し、停止、ロールバック、監査ログ、責任者通知 / To discover: 承認抜け、停止不能、説明不足、監査不能、責任分界不明
```

**説明:** AIの判断や操作に対して、人間が適切に介入できるかを見るチャーター。

**使用する時:** AIによるコード変更、メール送信、顧客対応、チケット更新、データ変更、契約/決済/削除などの重要操作。

**サンプル操作の流れ:**

1. AIが行う重要操作と承認が必要な境界を定義する
2. 通常操作で承認フローを確認する
3. 危険操作、曖昧な指示、権限外操作、緊急停止を試す
4. 差し戻し、修正依頼、ロールバック、監査ログを確認する
5. 誰が何を承認したか、後から追えるかを記録する

**主な成果物:** 承認フロー不備、監査ログ不足、AIガバナンス改善案
